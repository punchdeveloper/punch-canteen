# Rebuild notes (v63 → Next.js)

What changed when the v63 prototype was rebuilt, and where each review
finding was fixed. v63 = `PUNCH-Canteen-v63-Staff-Review-Improvements`
(single `index.html` + Supabase), reviewed on 26 and 30 October 2026.

## Approach

* **Same design.** The v63 CSS was measured on the live site (every screen, at
  1280/768/390 px) and only the 500 rules actually in use were carried over
  (`src/app/styles/v63.css`, generated by `scripts/build-canteen-css.mjs`,
  then trimmed by `scripts/prune-unused-css.mjs`). Markup and class names
  match v63. Fixes live separately in `src/app/styles/fixes.css`.
* **Same rules, enforced on the server.** v63's database functions
  (`place_order`, `confirm_wallet_topup`, `credit_weekly_ticket`, …) were ported
  to `src/server/*` with the same behaviour. The browser never talks to the
  database; every API checks the signed-in person's role and status first.
* **Data:** the real menu (with photos), staff directory, Today's Special and
  bank account were seeded from the live site on 31 Oct 2026. Orders, top-ups,
  reviews and chat were test data and were not copied.

## Database check findings → fixes

| Finding | Fix |
| --- | --- |
| Removed/deactivated admins could still credit tickets and confirm top-ups | Every request re-reads the user; removal/suspension also deletes their sessions |
| Master-admin protection was never installed | `users.is_master`, enforced in `src/server/staff.ts` (+ tests) |
| Operators could edit any column of any order | Orders only move received → ready → collected, server-checked |
| Balances drifted from the transaction history (expiry, resets) | All balance changes go through `src/server/ledger.ts`; `checkLedger()` verifies |
| Unlimited anonymous guest orders | Rate-limited per IP; phone number validated |
| "Clear test data" live on the real database | Only when `ENABLE_MAINTENANCE_TOOLS=true`; ledger stays consistent |
| Reviews not tied to orders | `reviews.order_id`, server-checked |
| Chat didn't record which operator replied | `chat_messages.sender_id` |
| Split payments recorded as just "wallet" | `orders.weekly_ticket_kobo` + `orders.wallet_kobo` |
| Staff directory and profiles duplicated people | One `users` table |
| Debt payment type unused | Removed |

## Deliberate small differences from v63

* The sidebar highlights the current page (v63's CSS had the style but a
  leftover script removed the highlight).
* Operator sections show counts, e.g. "Live Orders (2)".
* Navigation uses real links (keyboard, back button and middle-click work).
* Guests are taken to their order status after paying (v63 showed the
  reference only in a 4-second message).
* The "Overview / Quality checks / Reported issues" screens were dead demo
  code (browser-only, not linked) and were not ported.
* The sign-in form no longer reveals whether an email is in the directory.
* "CANTEEN" is white in the dark portal sidebar (blue failed contrast).
